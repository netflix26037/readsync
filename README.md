# ReadSync — نسخة Vercel + Upstash Redis (بيانات دائمة، تعمل من أي مكان)

## الفكرة

نفس التطبيق: قارئ RSS شخصي برمز دخول واحد، وحالة "مقروء" تُزامن بين أجهزتك.
الفرق عن النسخة المحلية: هذه النسخة تعمل كسيرفر حقيقي على الإنترنت (وليس على
شبكتك المنزلية فقط)، وتُخزّن البيانات في **Upstash Redis** — قاعدة بيانات
مجانية سحابية تبقى بياناتها محفوظة دائمًا (بخلاف تخزين الملفات على Vercel
الذي يُمسح مع كل طلب).

## الخطوة 1: أنشئ قاعدة بيانات Upstash مجانية

1. اذهب إلى https://console.upstash.com وسجّل حسابًا (مجاني).
2. أنشئ قاعدة بيانات جديدة (Create Database) من نوع Redis.
3. من صفحة القاعدة، انسخ قيمتين من قسم REST API:
   - `UPSTASH_REDIS_REST_URL`
   - `UPSTASH_REDIS_REST_TOKEN`

## الخطوة 2: انشر المشروع على Vercel

1. ادفع مجلد المشروع هذا إلى مستودع GitHub جديد أو موجود.
2. اذهب إلى https://vercel.com → Add New → Project → اختر ذلك المستودع.
3. قبل الضغط على Deploy، افتح **Environment Variables** وأضف:
   - `ACCESS_CODE` = الرمز الذي تريده (مثلاً 5566)
   - `JWT_SECRET` = أي نص عشوائي طويل تختاره
   - `UPSTASH_REDIS_REST_URL` = القيمة من الخطوة السابقة
   - `UPSTASH_REDIS_REST_TOKEN` = القيمة من الخطوة السابقة
4. اضغط Deploy. بعد انتهاء البناء ستحصل على رابط دائم مثل:
   `https://your-project.vercel.app`

افتح هذا الرابط من الكمبيوتر أو الجوال وسجّل الدخول بنفس `ACCESS_CODE` —
البيانات محفوظة في Upstash، فستكون نفسها من أي جهاز وفي أي وقت.

## التشغيل محليًا (اختياري، للتجربة قبل النشر)

```bash
cp .env.example .env
# عدّل القيم داخل .env: ACCESS_CODE, JWT_SECRET, وقيم Upstash
npm install
npm start
```

ثم افتح `http://localhost:3000`.

## الترجمة التلقائية للعربية

كل مقالة جديدة تُترجم تلقائيًا (العنوان والوصف) عبر خدمة MyMemory المجانية —
بدون أي مفتاح API أو حساب (بخلاف Azure Translator، لتفادي مشاكل بيانات
الاعتماد). كل مقالة تُترجم مرة واحدة فقط عند إضافتها لأول مرة، وتُحفظ
الترجمة بشكل دائم في Upstash — فلا تُعاد ترجمتها عند كل تحديث.

ملاحظة: الخدمة المجانية لها حد يومي بسيط للاستخدام لكل IP، وهذا كافٍ
تمامًا للاستخدام الشخصي (عدد محدود من المصادر والتحديث اليدوي).

## بنية المشروع

```
app.js           تعريف تطبيق Express وكل الـ API (بدون تشغيل سيرفر)
server.js        نقطة الدخول للتشغيل المحلي (يستدعي app.listen)
api/index.js     نقطة الدخول التي يستخدمها Vercel (نفس app.js كدالة serverless)
vercel.json      يوجّه كل الطلبات إلى api/index.js
store.js         طبقة التخزين، تتحدث مع Upstash Redis بدل ملف JSON
translate.js     الترجمة التلقائية عبر MyMemory (مجانية، بدون مفتاح)
public/index.html   الواجهة — تصميم بطاقات مع صور وتصنيفات وعناوين مترجمة
```

## لماذا لا يعمل هذا على GitHub Pages؟

GitHub Pages يستضيف ملفات ثابتة فقط (HTML/CSS/JS) ولا يستطيع تشغيل كود
سيرفر (مثل `app.js`). لذلك لا يمكن نشر هذا المشروع هناك مباشرة — Vercel هو
البديل الصحيح لأنه يشغّل الكود الخلفي كدوال serverless مجانًا.

## أول 3 أشياء أقترح تطويرها بعد ذلك

1. **حماية إضافية**: أضف حدًّا لعدد محاولات تسجيل الدخول الخاطئة (rate
   limiting) حتى لا يحاول أحد تخمين `ACCESS_CODE` بلا نهاية.
2. **تحديث تلقائي للمصادر**: أضف Vercel Cron Job (مدعوم مجانًا) يستدعي
   `/api/feeds/:id/refresh` لكل مصدر كل ساعة، بدل الاعتماد على الزر اليدوي.
3. **نسخ احتياطي**: بما أن كل شيء الآن في Upstash، فعّل النسخ الاحتياطي
   التلقائي المتاح في لوحة Upstash (أو صدّر البيانات دوريًا) تحسبًا لأي خطأ.
